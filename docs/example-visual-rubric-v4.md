## 1. 六级验收项（L0–L5），逐题打分

每个 Lab 必须给出 L0–L5 的判定（pass / fail / n-a）与证据位置。

### L0 数学正确性（一票否决）
- 题干数值、单位、结果、四舍五入、整除性必须正确；
- 图形必须**按真实比例尺**绘制，禁止"假映射"（如 1 米画 60px、100 米画 74px）；
- 禁止**循环论证**：不得先由结论反推出中间量、再代回公式"验证"结论。
- 证据：`test/unit/*.test.ts` 里有可复算的断言（坐标/面积/整数性/单位），或数据层与课本 OCR 的对照。

### L1 教材对齐
- `page` / `prompt` / 参数默认值 / 情境必须能在 `gX/ocr/upper/book/上册_正文.md` 找到出处；
- 结论用词与课本黑体字一致（如"面积 = 底 × 高"不能写成"周长"）；
- 证据：改稿里引用 OCR 原文行号或页码。

### L2 形数同帧
- 图形上的量（边长、格数、份数、角度）与右侧结果/算式**同屏同步**，任何参数变化两者同时变；
- 图上有**尺寸线 / 单位方格 / 刻度 / 直角与对应点标记**中至少两项，且标注量与数值一致。
- 证据：组件测试断言"参数 X = k 时 SVG 里出现某标注/某坐标"，或截图可目视核对。

### L3 过程可分步（本轮 g2–g4 的主攻点）
- 至少一个**真操作**按钮（剪一剪/拼一拼/数一数/分一分/对折/转/抛/放一块），点击后**图形状态真的改变**（不是只换一句话）；
- 结论态（"所以 S = ah"）只在操作之后出现，初始态不剧透；
- 过程态用同一份数据重算，不能画两套互相矛盾的数据。
- 证据：`<id>-act.png` 截图 + 组件测试断言"点击前后 DOM 结构/数据发生变化"。

### L4 师用/学用价值
- 一条"先想一想，再看提示"的概念追问（对应课本该例题要建立的概念），点击后才给答案；
- 一条易错点或追问（如"斜边越长面积会变大吗？"），能直接当课堂追问用；
- 结论文字教师可直接念、学生可自检。
- 证据：组件测试断言追问默认收起、点击后展开；或截图。

### L5 渲染健康
- 页面无 console error / pageerror，`main` 非空，无 Nuxt 组件解析告警；
- 证据：`scripts/visual-shots.mjs` 不产出 `<id>.notes.txt`。

## 2. 判定与优先级

| 判定 | 含义 | 处理 |
| --- | --- | --- |
| **P0 真错误** | L0 失败（算错、单位错、假比例尺、循环论证） | 本轮必须修 |
| **P1 空转** | L0 过但 L3 失败（静态图当过程、只换文字不换图） | 本轮必须修 |
| **P2 缺支撑** | L2/L4 缺项（无标注、无追问） | 本轮尽量修 |
| **P3 打磨** | 视觉细节、文案 | 有余力再修 |

## 3. 每个 Lab 必须交付的证据

1. 代码改动（组件/数据/工具函数）；
2. **断言**：`test/unit/` 或多 Lab 共享的几何模块测试，或 `test/component/labs.test.ts` 里对该 Lab 的行为断言；
3. **两张截图**：`docs/visual-review-screenshots/gX/<id>.png`（初始态）与 `<id>-act.png`（一次操作后的过程态）；

## 4. 纪律

- 只改自己负责的年级目录；**不要改** `shared/`、根 `README.md`、`docs/example-visual-improvements.md`（由 Lead 汇总）；
- 保持 `npx vitest run` 与 `npx vue-tsc --noEmit` 全绿，基线测试不许删、不许跳过；
- 断言必须能真的失败：改坏实现应当红（本地自查一次）；
- 不许把"参数滑到别的值"当成过程态；不许用 CSS keyframe 假装几何拼合；
- 结论先行、不剧透；文本少而准（课堂上一句话能念完）。
