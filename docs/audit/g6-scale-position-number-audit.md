## 2. 逐 Lab 审查

### 2.1 `g6-c1`-类之外：ScaleLab · `scale-shape`（图形的放大与缩小）
**文件**：`g6/game/src/components/labs/ScaleLab.vue:14-52, 65-115`；数据 `g6/data/upper/chapters/c6.ts:5-21`；计算 `compute.ts:508-523`

**数学核对通过**
- 三种图形的 scale 函数把每个顶点坐标同乘 f（ScaleLab.vue:21-37），是真正的位似放大：长方形 64×32→128×64、直角三角形 64×48→128×96、梯形 4 顶点同乘 f，对应角不变、对应边比恒为 n:d ✅
- 底边/高两条对应边用同一 f 绘制并同色标注（:44-49），与教材 p095"对应边长的比是 2:1"一致 ✅
- **面积 n² 的观察在本 lab 内是可验证的**：两幅图都用 `cell = 16`（:18），刻度相同；长方形 4×2=8 格 → f=2 时 8×4=32 格 = 8×2²；直角三角形 4×3=6 格 → 24 格 = 6×4 ✅（只是界面上没有把"面积"写出来）
- 面积倍数本身由练习 lab 覆盖且算式正确：`exercises/c6.ts:14-19`，`triArea=a²/2`、`scaledArea=a²n²/2`、`times=n²`、`trapScaled=trapArea/d²`

**问题**

**S-1（P1）n=d 时方向判错**
- 现象：n=2、d=2 时标题显示"长方形 按 **2:2** 的比**缩小**（每边 ×1）"。
- 证据：ScaleLab.vue:19 `isBigger = n > d`，:67 用 `isBigger ? '放大' : '缩小'`；n=d=2 → f=1 → 走"缩小"分支。而 compute.ts:512 `ratio > 1 ? '放大' : ratio < 1 ? '缩小' : '不变'` 对同一组参数判"不变"（:521 还写"大小不变"）→ 卡片与步骤文案互相打脸。参数 c6.ts:15-16 的 n、d 均为 1~4，n=d 有 4 组可达。
- 影响：学生会看到"按同一比缩小、每边 ×1"这种自相矛盾的结论；对比 b 中轴概念（×1 不变）被破坏。
- 改法：把 :19/:67 改成三分支（`f>1 放大 / f<1 缩小 / f=1 形状、大小都不变`），并顺手化简比（2:2 → 1:1）。

**S-2（P1）对应边标签被画布裁切**
- 现象：缩小情形下"64 → 32（×0.50）""32 → 16（×0.50）"文字左右被切；放大图里的高标签同样左半截丢失。
- 证据：标签用 `text-anchor="middle"` 放在 `x = 12`（高度标签，:88、:105）与 `x = baseLen*f/2`（底边标签，:104）。字符串约 12 个字符（含全角括号），10px 字号下宽约 70~80px，中点在 x=12 时向左延伸到 x≈−28，超出 viewBox 左边界；缩小图 `sW = ceil((64*0.5+12)/16) = 3`（:51）→ viewBox 仅 48px 宽，标签中点 x=16，跨度约 −21~53，两端都被裁。`<svg>` 根元素默认 `overflow:hidden`，不会外溢显示。
- 影响：最需要看清"每条边都 ×0.5"的缩小场景，关键数据反而看不见。
- 改法：`sW/sH` 预留文字宽度，例如 `Math.ceil((baseLen*f + 96)/16)`；或把标签移到图形正下方居中并令 `text-anchor="start"`；原图面板同理给 x=12 的标签加左内边距。

**S-3（P1）缺"面积是原来的几倍"**
- 现象：无论怎么拖，都看不到面积数据。
- 证据：教材 p099（书页 97，练习十二第 6 题）明确问"等腰直角三角形放大后的面积是原来的多少倍？直角梯形缩小后的面积是原来的几分之几？"；而 ScaleLab.vue 全文没有面积输出（`grep` 无"面积"），n² 只在练习 lab `exercises/c6.ts:14-19` 出现。c6.ts:8 的 `scale-shape` 例题本身书页 93 不含面积，故属"例题 lab 与练习 lab 分工"，但审查清单要求在本 lab 验证 n²。
- 影响：例题页无法回答教材紧随其后的面积追问；学生会以为面积也按 n 倍变化。
- 改法：在 :109-114 的说明区加一行动态面积比：`面积 ${cellRowsOrig} 格 → ${...} 格（×${n*n}），是边长的 ${n}² 倍`，数据可由 (base*f)*(height*f) / (base*height) 直接算。

**S-4（P2）梯形的高线画在图形外**
- 现象：选"梯形"时蓝色高线贴着左边框，落在梯形外部。
- 证据：ScaleLab.vue:43 对 shape=2 取 `heightLen=32`，:46 画 `M 0 32 L 0 0`；梯形左边是 (0,32)→(16,0)（:34），x=0 的竖直线段除端点 (0,32) 外全在图形外。
- 影响：看起来像"高在图形外面"，与"高是两条平行线之间的距离"混淆。
- 改法：梯形的高改画内部竖线（如 `M 8 32 L 8 0`）或用两条平行线的距离标注。

**S-5（P2）`shape===2 ? 64 : 64` 死分支**（:42）：两个分支同值，底边语义（梯形上底 32 / 下底 64）未体现；建议直接 `const baseLen = 64` 并补注"标注下底"。

### 2.2 ScaleLab · `map-scale`（比例尺）
**文件**：ScaleLab.vue:54-59, 117-144；数据 c6.ts:22-37；计算 compute.ts:524-538

**数学核对通过**
- `actualM = cm × scaleDen ÷ 100`（:57）：1:1000、图上 5cm → 5000cm = 50m；1:500、1cm → 5m；与教材 p100"图上 1 厘米表示实际 10 米"（1:1000）一致 ✅
- `perM = scaleDen/100`（:58）单值换算正确，且 scaleDen ∈ {500…10000, step 500} 全为 100 的倍数 → 换算恒为整数，不会出现除不断 ✅
- 换算流程条（:133-139）"× 比例尺分母 → 厘米 ÷100 → 米"与教材思路一致，且用的都是同一个 cm，无中间取整 ✅

**问题**
- **M-1（P1）只覆盖一个方向**：模板只有"图上→实际"（:140-142）。教材 p101 还有两种题型：①已知实际距离求图上距离（第 4 题 5cm/1:8000；反算 400m→5cm）；②量出图上距离求比例尺（练一练 2：15km）。另外教材 p101 用线段比例尺 `0 10 20 30m` 呈现。影响：学生练不到"实际→图上"和"求比例尺"，也见不到线段比例尺。改法：加 `mode` 参数（0 求实际 / 1 求图上 / 2 求比例尺），并把 `scaleDen` 换成可选列表（1000、8000、1500、2200000 —— 注意 c6.ts:32 的 min/max/step 使 1500、2200000 **不可达**），额外渲染一条带 0/10/20/30 刻度的线段比例尺。
- **M-2（P2）读数条封顶失真**：ScaleLab.vue:59 `barPx = min(cm*34, 320)`；cm=9.5 → 323→320，cm=10 → 340→320，两条 ruler-bar 一样长，但实际距离是 95m 与 100m。改法：去掉 320 封顶或按当前 cm 最大值归一化（`cm/10*100%`）。
- **M-3（P2）`fmt(scaleDen)/100` 与 1:n 表述**：compute.ts:536 用"比例尺 N 分之一（1:N）"表述，配合 `fmt()` 对整数正常；但结论里没有给出"实际:图上 = N:1"这一教材强调的另一种读法（p100 两种读法都有）。建议补一句。

### 2.3 PositionLab · `coordinate`（用数对确定位置）
**文件**：`g6/game/src/components/labs/PositionLab.vue:13-17, 59-88`；数据 `c7.ts:5-20`；计算 `compute.ts:541-554`

**数学核对通过**
- 结论串"第 col 列第 row 行 → 数对（col，row）"（:83-85）严格先列后行，与教材 p106"严军坐在第 3 列第 4 行，可以用数对（3，4）表示"一致 ✅
- 参数边界与网格一致：c7.ts:15-16 的 col∈[1,8]、row∈[1,6] 正好等于 :16-17 的 `COLS=8`、`ROWS=6`，不会越界或出现空行 ✅
- 交叉高亮（列高亮 + 行高亮 + 交点 active）在逻辑上等价于"第 c 列 ∩ 第 r 行"唯一点 ✅

**问题**

**C-1（P1）表头列号与列按钮错位**
- 现象：网格上方的列号被挤在左侧，与它标号的列不对齐；高亮第 3 列时，表头"3"落在约第 1~2 列按钮上方。
