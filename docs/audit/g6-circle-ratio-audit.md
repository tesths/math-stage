## 零、跨 Lab 共性问题（先看这 4 条）

### 0.1 `toFixed2` 把一切比值/占比压到 2 位小数（影响 3 个 Lab）

- **现象**：`0.618 → "0.62"`、`30/360 → "0.08"`、`45/360 → "0.13"`、`2/3 → "0.67"`。
- **证据**：`math.ts:56-58`
  ```ts
  export function toFixed2(v: number): string {
    return Number.isInteger(v) ? String(v) : v.toFixed(2).replace(/0+$/, '').replace(/\.$/, '')
  }
  ```
  凡非整数一律 `toFixed(2)`。调用点：`RatioLab.vue:97`（倍数）、`:109`（比值）、`:238`（黄金比）、`CircleLab.vue:199`（扇形占比）；`compute.ts:9` 的 `fmt()` 同样基于它，故**右侧「分步思考」栏也一起错**（`compute.ts:438,441`）。
- **影响**：**数学错误（表达层面）**。课本对这几个数有明确的小数位要求：
  - `p052.txt`（书页 50）第 6 题：“计算这些长方形的宽与长的比的比值（**精确到三位小数**）”；
  - `p067.txt`（书页 65）：“除不尽的得数**保留三位小数**”“从 21：34 开始，每个比的比值都接近 **0.618**”；
  - `p087.txt`（书页 85）第 10 题问的是“每个扇形的面积是所在圆面积的**几分之几**”。
  现在黄金比显示 0.62、30° 扇形占比显示 0.08（真值 1/12 = 0.0833…），两头不靠。
- **改法**：`math.ts:61` 已有 `toFixedN(v, digits)` 但目前**只在单元测试里被引用，产品代码一处未用**（`g6/game/test/unit/math.test.ts:27-29`），直接用即可：
  - 黄金比：`toFixedN(gw / gl, 3)` → `0.618`；
  - 扇形占比：用约分分数 `const g = gcd(angle, 360); `${angle/g}/${360/g}``（`gcd` 见 `math.ts:68`），并附 `≈ toFixedN(angle/360, 3)`；
  - 循环小数的倍数/比值：显示 `ra/rb` 分数或 `toFixedN(...,3)`。
- **优先级 P1**（各 Lab 内已单列）。

### 1. `g6-c5-circle-feature` — 认识圆（书页 70）

- **文件/行**：`CircleLab.vue:14-25`（计算）、`144-167`（模板）；数据 `c5.ts:5-17`；计算 `compute.ts:422-433`。
- **课本依据**：`p072.txt`（书页 70）“针尖所在的点是圆心…连接圆心和圆上任意一点的线段是半径…通过圆心并且两端都在圆上的线段是直径…d = 2r”✅。

**数学核对通过**

1. `d = 2r`：`cr=4 → cd=8`（`CircleLab.vue:17`），与 `compute.ts:425` 的 `value: 2r` 一致。
2. 半径线端点 `(170, 120−crPx)` 落在圆 `(cx=170, cy=120, r=crPx)` 上；`extraRadii`（`:20-25`）用同一个 `crPx` 计算两条 30°/−45° 的虚线半径，端点也在圆上 → “同圆所有半径相等”演示成立。
3. 直径线 `x` 从 `170−crPx` 到 `170+crPx`（`:153`），长度 = `2·crPx`，与半径线同圆心。
4. `r` 参数 1..8（`c5.ts:14`）与组件、compute 三处一致。

**问题**

**C1-1｜r=8 时圆被视口裁切，半径箭头的箭头也画不出来**
- **现象**：把半径拉到最大 8 厘米，圆的上、下边缘被 SVG 边界切平，垂直半径线的箭头（`marker-end`）落在视口外不可见。
- **证据**：`CircleLab.vue:16` `crPx = cr*16`、`:18-19` `CX=170, CY=120`、`:143` `<svg :width="340" :height="240" viewBox="0 0 340 240">`。推算：r=8 → crPx=128 → 圆纵向 [120−128, 120+128] = **[−8, 248]**，超出 0..240；`:152` 半径线终点 y = 120−128 = **−8**，同样在视口外。
- **影响**：表达缺陷（图形被裁，几何关系看不全；数值不错）。
- **改法**：比例尺自适应：`const k = Math.min(16, 100 / cr.value); const crPx = computed(() => cr.value * k)`（r=8 → k=12.5 → crPx=100，圆纵向 [20,220] 完整放入 240）；或 `CY` 改 130 并把 `viewBox` 高度改为 `130 + crPx + 10`。
- **优先级 P2**

**C1-2｜课本同页的“圆是轴对称图形、有无数条对称轴”没有体现（可选补强）**
- **证据**：`p072.txt`（书页 70）“通过折一折，发现圆是轴对称图形，它有无数条对称轴”；`CircleLab.vue:144-165` 只有圆心/半径/直径三条线索。
- **影响**：表达缺陷（内容缺失，非错误）。
- **改法**：加 1–2 条过圆心的虚线（旋转动画）并标注“对称轴有无数条”。
- **优先级 P2**

### 2. `g6-c5-sector` — 扇形与圆心角（书页 72）

- **文件/行**：`CircleLab.vue:27-60`（计算）、`170-200`（模板）；数据 `c5.ts:19-30`；计算 `compute.ts:434-445`。
- **课本依据**：`p074.txt`（书页 72）“由一条弧和经过这条弧两端的两条半径围成的图形叫作扇形”✅；`p087.txt`（书页 85）第 10 题给出 30°/60°/75°/120° 并追问“面积是所在圆面积的**几分之几**”“弧长是所在圆周长的**几分之几**”。

**数学核对通过**

1. 扇形路径 `M O L A A r r 0 large 1 B Z`（`:40`）的填充区域就是圆心角 θ 的楔形；两条半径另有独立描边（`:176-177`），**两条半径与弧都画全**。
2. `large-arc-flag` 只有在 θ > 180 时为 1（`:39-40, 50`），`sweep-flag = 1`（屏幕上顺时针）与角度递增方向一致。逐点复算 θ=270°：起点 `(170,20)`、终点 `(70,120)`，正是从正上方顺时针转 270°，`large=1` 正确。
3. 圆心角弧画在半径 46 上（`:43-52`），角度标签放在角平分线半径 62 处（`:53-56`），不会与弧重叠。
4. “扇形占圆的比例 = 圆心角 ÷ 360°”与 `compute.ts:438` 的概念一致。

**问题**

**C2-1｜θ=360° 时弧退化，扇形整块消失**
- **现象**：把圆心角拉到最大值 360°，右侧只剩一条线段，扇形填充与圆心角弧都不见了。
- **证据**：`c5.ts:27` `{ key:'angle', min:30, max:360, step:15, default:90 }`；`CircleLab.vue:30-41` 计算 `start=-90`、`end=-90+360=270`，于是 `x1 = 170+100·cos(−90°) = 170`、`y1 = 20`，`x2 = 170+100·cos 270° = 170`、`y2 = 20` —— **起点与终点完全重合**。按 SVG 规范，`A` 命令两端点相同时该弧段被忽略，路径退化为 `M 170 120 L 170 20 Z`（零面积）；`:43-52` 的 `angleArc` 同样重合于 `(170,74)`。
- **影响**：**数学错误**（360° 的扇形就是整个圆，图上却什么都没有）。
- **改法**：加特例：
  ```ts
  if (angle.value % 360 === 0)
    return `M ${CX - sr} ${CY} a ${sr} ${sr} 0 1 0 ${2*sr} 0 a ${sr} ${sr} 0 1 0 ${-2*sr} 0 Z`
  ```
  或把参数改成 `max: 345`。
- **优先级 P1**

**C2-2｜“面积占全圆的 ___”用 2 位小数，与课本“几分之几”的要求不符，且出现不合格近似**
- **现象**：30° 显示“面积占全圆的 **0.08**”，45° 显示 0.13，60° 显示 0.17。
- **证据**：`CircleLab.vue:199` `{{ toFixed2(angle / 360) }}`；`math.ts:57` 的 `toFixed(2)` —— 30/360 = 0.08333… → `"0.08"`、45/360 = 0.125 → `"0.13"`、60/360 = 0.16667 → `"0.17"`。`compute.ts:438, 441` 用 `fmt()`（= `toFixed2`，`:9`）输出同样的 0.08。课本 `p087.txt` 第 10 题对应的答案分别是 **1/12、1/6、5/24、1/3、1/4**。
- **影响**：**数学错误（表达）**：0.08 既不是精确值也不是可接受的近似（1/12 = 0.0833…，两位小数应写 0.08 但教学目标是分数）。
- **改法**：显示约分分数并附三位小数：
  ```ts
  const fracText = computed(() => { const g = gcd(angle.value, 360); return `${angle.value/g}/${360/g}` })
  ```
  → 30° → `1/12 ≈ 0.083`；`compute.ts:438,441` 同步改。
- **优先级 P1**

**C2-3｜扇形没有半径参数，也没有弧长/面积数值，课本要查的两个公式在本 Lab 无法验证**
- **现象**：图中圆的半径恒为 100 px 且无单位（不是米/厘米）；文字只有“圆心角 θ°”和占比小数，看不到 `弧长 = 2πr·θ/360`、`面积 = πr²·θ/360` 的任何数值。
- **证据**：`CircleLab.vue:29` `const sr = 100`（硬编码像素）；`c5.ts:27-29` params 只有 `angle`，`formula` 只写“扇形占圆的比例 = 圆心角 ÷ 360°”；`compute.ts:434-445` 的 steps 也只有角度与占比。
- **影响**：表达缺陷（内容缺失）：`p087.txt` 第 10 题三条追问（圆心角度数、面积占比、**弧长占比**）只覆盖了前两条的一半；“圆心角越大扇形越大”也只能靠肉眼，因为半径固定且没有弧长。
- **改法**：加半径参数（1..10 厘米）并让 `sr = r * 12`；结果行补两式，例如 r=5、θ=90° 时 `弧长 = 2×3.14×5×(90/360) = 7.85 厘米`、`面积 = 3.14×5²×(90/360) = 19.625 平方厘米`（复算值）。
- **优先级 P1**

### 3. `g6-c5-circumference` — 圆的周长 · 圆周率（书页 77）

- **文件/行**：`CircleLab.vue:62-67`（计算）、`202-216`（模板）；数据 `c5.ts:32-43`；计算 `compute.ts:446-458`。
- **课本依据**：`p078.txt`（书页 76）绕绳/滚圆测周长、`p079.txt`（书页 77）“任意个圆的周长与它直径比的比值都是一个固定的数…圆周率…3.141592653…解决问题时一般把圆周率保留两位小数，取 3.14”，以及“一个圆形喷水池的半径是 14 米”✅。

**数学核对通过**

1. r = 14 → `C = 2×3.14×14 = 87.92 米` ✅ 与课本例题一致；`CircleLab.vue:65` 与 `compute.ts:448`（`roundTo(...,2)`）同值。
2. `C ÷ d = 87.92 ÷ 28 = 3.14`，与 π 的两位近似一致 ✅。
3. 圆的像素比例是准的：`cirPx = Math.min(5r, 150)`，r ≤ 30 时 `min` 不生效（r=30 → 150 = 5×30），即 5 px/米；直径线长度 `2·cirPx`（`:207`）与圆一致 ✅。
4. π 取 3.14 与课本“一般取 3.14”一致（`CircleLab.vue:12`、`compute.ts:15`）。

**问题**

**C3-1｜“展开周长”被 `min(·, 260)` 截断，图上量出的 C÷d ≈ 1.86，而不是 π**
- **现象**：默认 r = 14 米时，图上圆的直径是 140 px，而下方代表“展开后的周长”的线段只有 260 px，图上文字还写着“展开周长 C = 2πr ≈ **260px**”。
- **证据**：`CircleLab.vue:64` `cirPx = Math.min(cir*5, 150)`（r=14 → 70 px，直径 140 px）；`:67` `unfoldPx = Math.min(2*PI*cirPx, 260)` → 真实应为 `2×3.14×70 = 439.6 px`，被截成 **260**。推算：**260 ÷ 140 = 1.857 ≠ 3.14**；r = 30 时更糟：`cirPx = 150`、直径 300 px、展开线仍是 260 → **0.867**。
- **影响**：**数学错误（图形）**：这张图正是用来说明“周长是直径的 π 倍”，学生在图上量出来的比例是 1.86（甚至 0.87），会直接推翻结论。
- **改法**：保持同一比例尺并让线段放得下：
  ```ts
  const k = computed(() => Math.min(5, 300 / (2 * PI * cir.value)))
  const cirPx = computed(() => cir.value * k.value)      // r=14 → 3.412 → 47.8px
  const unfoldPx = computed(() => 2 * PI * cirPx.value)  // ≈ 300px
  ```
  复算：300 ÷ 95.6 = **3.138 ≈ π** ✅；或把 `viewBox` 加宽到约 2π×150 ≈ 942 px 并用横向滚动容器，取消截断。
- **优先级 P0**

**C3-2｜图上长度用 px 显示，与同一张图里的“米”并列，单位混乱**
- **现象**：同一 SVG 里同时出现“C = 87.92 **米**”（`:212`）和“展开周长 C = 2πr ≈ 260 **px**”（`:209`）。
