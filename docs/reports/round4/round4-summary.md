**这一轮真正修好的，不只是 249 个可视化里的一部分图形，而是"证据链"本身。**
优化前六册宣称"79/80 已达标""过程态截图齐全"，实测其中 **66 张过程态截图与初始态逐字节相同**（g5 24/33、g6 42/47）——

### 2.3 证据链工具本身也修了（`scripts/visual-shots.mjs`）

这是本轮最容易被忽略、但影响最大的一处："截图回归工具"原先会**静默产出假证据**。

| 缺陷 | 后果 | 修法 |
| --- | --- | --- |
| 只点 20 个固定文案的按钮 | g5/g6 的"逐级翻倍 · 下一档 16 份""量下一条对应边"等按钮一个都不命中 → 66 张 `-act.png` 是初始态 | 文案扩到 38 个 + `[data-act]` 兜底 + 组件里给主操作按钮打 `data-act` |
| 固定 `waitForTimeout(600)` 后点击 | Nuxt 客户端二次挂载，点击落在"将被丢弃的实例"上，状态被重置 | 换成**水合哨兵**：等 `#__nuxt.__vue_app__` 存在且 body 文本连续两次采样不变 |
| 没有"这一下到底生效没有"的判断 | 点击被吞也照常截图 | 点击前后取 Lab 区域 DOM 指纹；无变化就重点一次；**截图前再校验一次**（有些页在点击之后才二次挂载） |
| 渲染进程偶发崩溃会 abort 整批 | 前面几十张白跑 | 单题 try/catch + 重建 page，问题记到该题 |
| 没有自检 | 「假过程态」无人发现 | 每张 `-act.png` 与初始态比 **md5**，相同即打印 `⚠` 并汇总；`点击后无变化` 单独计数 |

现在任何人跑一遍都能看到结尾三行：`N 个页面有问题` / `假过程态 0 个` / `点击后无变化 …个`。

两个使用陷阱（本轮踩到并写进脚本注释）：
- **同一端口上残留旧 dev server**：`localhost` 先解析 `::1`，旧实例会"接走"请求，于是你看到的是旧代码（本轮因此一度在截图里看到已删掉的调试日志）。跑回归前先确认端口上只有一个实例，并优先用 `--host 127.0.0.1`。
- **`点击后无变化` 不等于假证据**：多步循环题被多步推进两次后可能绕回第 1 步（`g6-c2-segment` 实测）。它只是提示，**判据以 md5 为准**。

## 3. 本轮修掉的 20 处 P0（真错误）分类

| 错误类型 | 例证（改前 → 改后） |
| --- | --- |
| **假拼合 / 假变换** | `g2-c3-tangram`：板子从未移动，"长方形"和"平行四边形"都写 ③④⑤ 同一组板 → 按课本原图实测坐标 + 刚性变换实现 6 种真拼法，断言"板面积之和 = 目标面积、拼合顶点集 = 轮廓顶点集" |
| **偷换操作数** | `g2-c7-twodigit-sub`：被减数 < 减数时静默交换两数并教"大数减小数"（36−54 → 18）→ 真值 + "本册不学负数" |
| **循环论证** | `g3-c4-equivalent`：用石头总数反推象重再比石头 → 固定象重 + `stonesToMatch`；`g5-pinboard-area`：由面积倒推内部钉子数再"验证"皮克定理 → 逐个点数 |
| **假比例尺** | `g5-c3-hectare-square`、`g3-c6-km-m`、`g4-c9-big-1yi`、`g5-c7-speed-car`、`g4-c4-mul-distance`：`60 + 边长×0.14`、`i<=km*10/3`、`min(140, 米/20)`、`min(320, s*2.6)` 这类"看起来等比、其实不是"的映射 → 统一改成真实比例尺并加断言 |
| **假等式 / 二次舍入** | `g5-c4-ddiv-eraser` 的 `9.6 ÷ 7 = 1.37143`、`g6-c5-circle-area` 的 `15.31 × 5 ≈ 76.54`、`g6-c2-segment-more` 的 `14 × 1.28571 = 18` → 改成"每份 1.3 元，余 0.5 元（≈1.37）"、`15.307 × 5`、`14 × (1 + 2/7)` |
| **单位错** | `g3-c6-km-m` 米→千米标成 ×10（应 ×1000）；`g5-c3-area-mcfield` 的"1800 格"（应平方米） |
| **硬编码与图形矛盾** | `g3-c11-views-cube` 硬写"前面 6 个方格一排"、`g5-pinboard-area` 面板说矩形面积 8 而图上数出 15（compute 与组件各写一份数据） |
| **边界没算** | `g3-c9-interval` 两端都放/只放一端/环形（`物体数 = 间隔数 ± 1`）、`g4-c5-mix-segment` 橘子数为负 → 负长度线段、`g3-c5-stat` 圆点被 `Math.min` 静默截断 |
| **教材错位** | `g5-c2-stats-table` page 17→18（17 页是住房面积）、`g5-c5-marble-bag` page 68→66（68 页是抛硬币）——断言直接读 OCR 原文校验 |

另有 **P1（静态图当过程）**：g2 22 个 Lab、g1 25 道题、g3/g4 共 12 个、g5/g6 共 3 个（`multiples-3`、`mul-decimal`、`div-approx`）都补了"点一次图形真的变"的分步操作；
**P2**：g3/g4/g5/g6 各若干标注重叠、页码错位、结论剧透等。

## 4. 关键发现：三种"看起来做到了"

1. **"有截图" ≠ "有过程态"**：`scripts/visual-shots.mjs` 只点 20 个固定文案的按钮，而 g5/g6 的按钮写成"逐级翻倍 · 下一档 16 份""量下一条对应边"，一个都没命中 →
   `<id>-act.png` 其实是初始态。**66 张假过程态**就是这么来的。
2. **"有数据" ≠ "页面在用它"**：`ConceptTip` 组件早已存在、`LabDef.tip` 每道题都写了，但 g2–g4 的 Lab 页**从不渲染**它。
   度量脚本一度输出"g2–g4 概念追问 100%"，其实是"tip 字段 100%，页面 0%"。本轮三册全部接上。
3. **"测试全绿" ≠ "数学对"**：基线 1376 条测试全绿时，屏幕上有 `9.6 ÷ 7 = 1.37143`、`15.31 × 5 ≈ 76.54` 这种照着抄就会错的式子——
   因为旧断言只检查"有没有渲染出结果"，不检查"等号成不成立"。本轮把"可复算"写进断言（鞋带公式、整数性、全区间性质）。

## 5. 诚实清单：本轮**没有**做到、因此**不能**宣称的

1. **没有学习效果数据。** 全部结论都是"图文自洽、算式成立、过程可见、可复算"——这是**必要条件，不是教学效果的证据**。要说"帮学生理解了"，需要前后测/课堂观察，本仓库没有。
2. **L2（量化标注）仍是最弱一维：106/249 只到 partial。** g1 78 个全 partial（一年级以点数为主动作，缺统一格点尺/刻度）、g2 21 个 partial（schema 无 `units` 字段，单位写不进数据层）。
3. **g1–g4 的数据 schema 没有 `units` 字段**（只有 g5/g6 有），所以"真实单位"在 g2–g4 恒为 0。这是**结构性缺口**，不是这一轮能补的。
4. **没有投影/全屏模式，也没有字号放大。** 实测六册都没有 `requestFullscreen`/缩放入口；g5 `NumberLab` 的数轴 `max-width: 644px`，在 1440px 宽屏上只占一半，下方大量留白。**课堂上"能看懂"和"后排能看清"是两件事。**
5. **过程态多为"先给结论、可回放"，不是"先做后看"。** 隐藏答案需要重写基线断言（g2 108 条、g6 若干），本轮选择保住基线，没做。
6. **无障碍没做**：过程按钮没有 `aria-live`，SVG 大多 `role="img"` 但无 `aria-label`（7 个 role=img 里只有 3 个有），读屏体验未验证。
7. **`g3-c11-views3d`** 只能转视角、**`g3-c7-translate`** 无斜向平移、**`g3-c10-segment-*`** 多段时标注挤压、**`g4-c9-big-1yi`** 珠峰仍是三角剪影：这 4 处如实留 partial。
8. **`g6-c4-ex-football-ratio` 的过程态依赖"等挂载稳定再点"**：本轮已把哨兵与"截图前再校验"写进脚本，重跑可复现（假过程态 0），但这类"二次挂载"页面在未来若变慢仍可能退回同图——脚本现在会打印 `⚠`，不会静默产出假证据。
9. **单元归属**：`g5-pinboard-area`（课本 110–111 页）从"因数与倍数"改挂到七单元末，理由是课本里它不是编号单元；这属于编辑判断，教材版本不同可能需要重判。

## 6. 回答"这些可视化到底能不能帮学生理解、帮老师教学"

**能，但方式和产品话术不一样。** 按证据强度分三层：

### 第一层：已经能直接进课堂（有可复算断言 + 过程态真变）
- **把黑板上"一次性的动作"变成"可回放的过程"**：`g5-c3-area-parallelogram` 点"数一数方格"后缺口三角形被平移补齐、24 格 × 100 平方米与真实比例尺同时出现——黑板剪纸做一次就没了，这里可以每次重来。
- **把"看不出来的逼近"变成"看得见的数字"**：`g6-c5-circle-area` 逐级翻倍 8→16→32→64，长从 3.061r 逼近 πr，差 0.401→0.164→0.047→0.014。"为什么越拼越像长方形"这个问题，静态图永远问不出来。
- **把"试商/调商"的决策过程显式化**：`g6-c1-div-approx` 一位一位试商（400÷60=6 余 40 → 666.6… → 末位 6≥5 进 1 → 666.67），`g4-c1-div-try` 初商偏大就调小。
- **把"错"设计成能被看见**：`g3-c3-mul-estimate` 的估大/估小/精算三值判定——学生自己就能发现"只估一次会判错"。

### 第二层：能帮老师，但要老师主动用
- 每题底部的 **「重点概念：课本第 N 页」+「先想一想，再看提示」**（本轮从 g5/g6 补齐到 g2–g4、g1）：老师能照念、能让学生先答再展开。这是六册之间**最有价值的一致性改造**。
- **每题的易错点一句话**：可直接当课堂追问。
- 但**没有"课堂脚本"**：哪个环节按哪个按钮、留几分钟、追问什么，仍需老师自己备课。

### 第三层：现在还不能宣称
- **学习效果**（无数据）；
- **后排看得清**（无投影/放大模式，图形偏小）；
- **学生自学闭环**（没有"我答错了，为什么错"的诊断，只有"图会变"）；
- **数值换算类题目本身的价值**（倍数/因数/试商/小数点移动这几类，做成"滑块 + 正确结论"后，学生滑到哪都对，**不需要思考就能得到答案**——这是本轮的判断，也是最该在下一轮改设计的一类）。

## 7. 下一轮建议（按性价比排序）

1. **给 `g1–g4` 的数据 schema 加 `units`**（一处 schema，六册统一），顺手把 L2 的量化标注（格点尺/单位方格/刻度）补到 g1/g2。
2. **加"课堂模式"**：全屏 + 字号/图形放大 + 隐藏分步文字（一键切换），成本低、对投影收益最大。
3. **数值换算类改成"判断/改错"型**：先给一个错答案让学生判断，再让图自己去验证——把"看结论"变成"做判断"。
4. **把"结论延后出现"做成配置项**，而不是删掉过程；重写受影响的基线断言。
5. **无障碍与窄屏**：`aria-live`、SVG `aria-label`、360px 以下布局（`g3-c2-time24` 双环钟面已知会挤）。
