## 0. 一句话结论

国际平台把"例题可视化"做成**可参数化的数学模型 + 分步揭示 + 同帧数值反馈**，
而不是"把课本插图做成会动的图"。可迁移到本仓库 Lab 的四条硬规则：

| 规则 | 依据 | 本仓库落地 |
|---|---|---|
| **1. 一个核心参数驱动整个模型** | GeoGebra 把滑动条当"动态变量赋值器"，一控多联动（[检索摘要](https://www.so.com/s?q=GeoGebra+%E6%BB%91%E5%8A%A8%E6%9D%A1+%E5%8A%A8%E6%80%81%E6%95%B0%E5%AD%A6)，仅见摘要）；Mathigon 圆面积只用一个"等分份数"滑块同时改变分割、拼合形状与近似程度 | Lab 的 `params` 必须包含**决定概念的那个量**（等分份数、斜边偏移、份数），而不只是题目数值 |
| **2. 形变与数变同帧** | 课标"几何直观 = 建立形与数的联系"（[课标 PDF](http://www.moe.gov.cn/srcsite/A26/s8001/202204/W020220510531636118932.pdf) 原文）；洋葱学园"图形—算式同步" | 图形旁边常驻 S/结果，滑动时同步刷新；推导链 chip 逐步点亮 |
| **3. 分步揭示，不抢先给结论** | PhET 的 implicit scaffolding / minimal text（[PhET Research](https://phet.colorado.edu/en/research)，已抓取）；Mathigon 的 "Continue / Reveal all steps" | 初始态只给模型与可操作项；点击"剪一剪/拼一拼/数一数/等分"后才出现完成态与验证语 |
| **4. 极限与逼近必须可调** | Mathigon 圆面积：滑块增加等分份数，"拼出的形状越来越像长方形"，并明确写出"高 = r、宽 = 半个圆周 = πr" | 圆面积 Lab 的"平均分份数"要能从 8 到 64 递增，并实时给出底/高的近似值 |

## 1. Mathigon（已抓取正文）

### 1.1 圆与 π：`https://mathigon.org/course/circles/introduction`

原文关键句（抓取）：

- "Here you can see a circle divided into *n* wedges. **Move the slider**, to line up the wedges in one row."（一个滑块同时控制等分数与排列方式）
- "**If we increase the number of wedges**, this shape starts to look more and more like a rectangle."
- "The height of the rectangle is equal to the **radius**. The width of the rectangle is equal to **half the circumference**."
- 还有第二条**等价**路径：把圆分成 `n` 个同心圆环，"uncurl" 成三角形，"height = radius, base = circumference"，同样得到 `A = πr²`。
- 圆周率部分：直径 1 的车轮"unroll"周长正好是 π；再用**正多边形逼近圆**（边数递增）演示 π 的来源。

**可迁移设计**：
1. 同一个结论给**两条不同的分割路径**（扇形→长方形、圆环→三角形），互相印证，避免学生把公式记成特例。
2. 逼近过程用**一个滑块控制离散化程度**，并同步显示"现在的底 ≈ ?、高 ≈ ?、与长方形的差距"。
3. 每个数值都**贴在图形上**（r、πr 直接标在长方形的边上），而不是只在公式区。

### 1.2 四边形面积：`https://mathigon.org/course/polyhedra/quadrilaterals`

原文关键句（抓取）：

- 平行四边形："On the left, **try to draw a rectangle that has the same area as the parallelogram**. Can you see that the **missing triangle on the left** is exactly the same as the **overlapping triangle on the right**?"
- 梯形："Can you see how the **missing and added triangles on the left and the right cancel out**? The width of the rectangle is the distance between the **midpoints** of the two non-parallel sides. This is called the **midsegment**."
- 明示提醒："Be careful when measuring the height of a parallelogram: it is usually **not** the same as one of the two sides."

**可迁移设计**：
1. 剪拼动画的判据不是"能变成长方形"，而是**左边的缺口 = 右边多出来的那块**。所以正确做法是：把缺口画成高亮轮廓，让剪下的图形**平移后正好落进缺口**（本仓库 `AreaLab` 已按此修正：平移量 = 底 a，而不是斜边偏移）。
2. 必须**显式画出"高"的落脚点与直角标记**，并提醒高 ≠ 斜边。
3. 梯形用**两腰中点**（中位线）视角补充：面积 = 中位线 × 高，与 (a+b)×h÷2 互相印证。

## 2. PhET（已抓取正文：<https://phet.colorado.edu/en/research>）

抓取到的设计研究要点：

- 设计原则来自**学习科学 + 逐个模拟的学生访谈**（每个模拟 4–6 次出声思维访谈），关注"哪些界面特征真正促进学习"。
- 关键概念 **implicit scaffolding（隐性支架）**：*"Guiding without feeling guided"*（Paul, Podolefsky & Perkins, 2012）——把引导做进界面结构（可拖拽对象、即时反馈、约束），而不是写成大段说明文字。
- **minimal text**：模拟"designed with minimal text so that they can easily be integrated into every aspect"，界面文字尽量少，留给课堂讨论。
- 强调**表征（representations）在类比中的作用**，以及"动画 ≠ 交互"（*Animation or Simulation: Investigating the Importance of Interactivity*, 2014）。

**可迁移设计**：
1. 图片区的文字只保留**量名 + 数值 + 单位**（本仓库的做法：`高 h = 4 格（40 米）`），解释性文字放到下方"分步思考"。
2. 引导靠**可操作项 + 约束**实现：滑块范围就是概念的边界（例如斜边偏移 0–3 格），不需要提示语教学生"拖我"。
3. 交互要真的改变模型（拖动即变），不要做成"点击继续"的伪交互。
4. 提供**初中生也能用的极简界面**：一层情境、一层模型、一层操作、一层抽象，不堆装饰。

## 3. GeoGebra / Desmos（仅检索到摘要与题录，未抓取官方文档正文）

- GeoGebra：检索结果一致描述其核心是**滑动条 = 动态变量赋值器**，"拖动一个滑块，可同步改变函数图像、几何坐标、颜色甚至逻辑阈值"（[360 检索摘要](https://www.so.com/s?q=GeoGebra+%E6%BB%91%E5%8A%A8%E6%9D%A1+%E5%8A%A8%E6%80%81%E6%95%B0%E5%AD%A6)）；教研文章强调其"**多元表征**"与"动态演示"用于**发现与验证猜想**（龙源期刊网《基于 GeoGebra 运用的数学教学设计》，仅见题录）。
- Desmos：官方帮助页在本会话被反爬拦截（HTTP 403），未取得正文；其 Activity Builder 的公开形态是"教师控制进度、学生逐屏操作"（**据产品公开形态归纳，未抓取**）。
- 对本仓库的直接启发：**同一个参数要联动多个表征**（图形 + 算式 + 步骤 + 高亮），这在 Vue 里就是"一个 `computed` 派生全部派生量"，不要各自维护状态。

## 4. 前端实现要点（本仓库技术栈：Nuxt 4 + Vue 3.5 + SVG + three.js + chart.js + anime.js）

### 4.1 SVG vs Canvas vs WebGL

| 场景 | 选择 | 理由 |
|---|---|---|
| 几何图形、方格模型、尺寸标注、数轴、统计图 | **SVG**（本仓库现状） | 可用 CSS 变量上色、可绑定响应式属性、可访问（`<text>` 可读）、格数在数百级时性能足够 |
| 100×100 小数方格 | SVG + 分层/`<pattern>` | 实测：10 000 个 `<rect>` 会明显卡顿；改为**只渲染有意义的格**（交点、重叠区、边界格），或用 `<pattern>` 一次填充 |
| 3D 三视图、积木 | **three.js** | 需要真实投影与相机；三视图必须**固定不随模型旋转**，另用 SVG 画投影网格 |
| 概率模拟收敛曲线、大样本频数 | chart.js / SVG 折线 | 点数多时优先 chart.js |

**踩坑记录（本仓库已遇到）**：
- 视口要**自适应图形外接框**，否则形状小时上方留大片空白（`AreaLab` 早期固定 `viewBox="0 0 420 430"`，已改为按 `bounds` 计算 `viewBox`）。
- 计量类图形（米/千米）**不能画单位方格**：36 米 × 54 米的麦田画成 1 米方格会产生 3600+ 个单元格，既慢又没有教学意义；改用**比例尺条**。

### 4.2 数学正确性必须可被测试

把剪拼几何抽成纯函数模块（本仓库 `g5/game/src/lib/labs/area.ts`），用**鞋带公式**在单元测试里验证：

- 剪下的三角形向左平移**一个底**后，顶点集合与左侧缺口完全相同；
- 原件 + 完全一样的复制件面积 = 拼成的平行四边形面积，且两组对边平行且相等；
- 图形顶点算出的面积 = 面积公式算出的面积。

这样"动画看起来对不对"变成"断言过不过"，避免用肉眼验收数学。

### 4.3 anime.js 用于过程动画的惯用写法

- **不要直接动画 SVG 属性字符串**（本仓库 g3 曾把 `y="36 + bi * 56"` 写成字符串导致浏览器报错）。
- 动画一个**数值 ref**，再用 `computed` 派生坐标字符串；动画结束后把 ref **吸附到精确终点**（避免浮点残差让"拼合"差 0.01 格）。
- 无限逼近类动画（等分份数）不要用补间，直接**按离散份数重画**，学生才能看清"每增加一次等分，形状更接近长方形"。

## 5. 与本仓库 Lab 的验收清单（每道题改完按此自查）

- [ ] 情境层：题目里的真实对象、单位、数量能从图上读出来。
- [ ] 模型层：有可操作的数学模型（方格/数轴/数位表/份数条/方位图/圆），不是只有公式框。
- [ ] 过程层：至少一个"操作按钮"能改变图形状态，且过程可见（剪拼/等分/进位/旋转/抽样）。
- [ ] 抽象层：图形变化与算式/数值**同帧**更新，步骤与图上高亮一一对应。
- [ ] 比例与单位：所有长度/面积按同一比例尺绘制，单位可换算（格 ↔ 平方米），不出现"24 格说成 24 平方米"。
- [ ] 可调参数包含**决定概念的那个量**（等分份数、斜边偏移、份数、圈数…）。
- [ ] 单元测试覆盖新几何/新公式；截图回归（`scripts/visual-shots.mjs`）无控制台报错。
