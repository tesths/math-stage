# 六册例题可视化升级实施规格

> 生成日期：2026-08-10  \
> 上游依据：`docs/example-visual-review.md`、`docs/example-audit-glm.md`、`docs/visual-review-screenshots/`  \
> 目标：把逐题 review 转成可直接实施的组件级改造任务，明确“改成什么样”。

## 1. 总体判断

现有 review 已经逐题写了改进方向，但粒度主要是“方案级”：例如“用数位表逐位高亮”“用扇形剪拼近似长方形”。本规格把这些方向收敛为组件任务，要求实施时不再逐题临场判断。

核心改法不是单纯美化，而是给每道例题补齐一条稳定证据链：

```text
课本情境/真实对象 -> 可操作数学模型 -> 图形变化过程 -> 算式/结论
```

每个可视化组件都应同时回答三件事：

- **看什么**：学生一眼能看出题目中的关键对象、单位、方向、数量关系。
- **怎么变**：拖动参数或答题时，关键量如何移动、分组、对齐、切分、拼合。
- **为什么这样算**：图形状态和下方分步思考必须一一对应。

## 2. 实施顺序

| 阶段 | 范围 | 目标 | 完成标准 |
|---|---|---|---|
| 0. P0 修复 | g1 图内数量题、`c6-count-02`、g3 `SegmentLab` SVG 错误 | 先消除误导和渲染错误 | P0 截图全部重新通过；`manifest` 无真实渲染错误 |
| 1. 低年级具象模型 | g1 `Count/Compare/Position/Ordinal/Split/AddSub/Ten` | 把 emoji 答题改成可数、可圈、可对齐的数学对象 | 每题可从图看出数量、起点、参照物和操作动作 |
| 2. 位值与竖式 | g2 `NumberLab/TwodigitLab`，g3/g4 乘除竖式 | 让进位、退位、落商、试商、位值对齐可见 | 每个步骤都有高亮位、来源量和结果量 |
| 3. 线段图与数量关系 | g3/g4/g6 `SegmentLab`、`QuantityLab` | 统一比例尺、括号/差量/倍量标注 | 同类线段按同一比例绘制，未知量显式标注 |
| 4. 几何与空间 | 运动、面积、圆、比例尺、三视图、位置 | 保证中心、轴、角、比例、投影关系准确 | 截图中能看到基准线、对应点、尺寸和比例 |
| 5. 数据/概率/代数 | 统计图、可能性、因数倍数、字母式 | 从实验/集合/变化情境抽象到公式 | 图表和公式联动，保留数据来源 |

## 3. 横向组件协议

### 3.1 建议新增轻量视觉配置

不要为每道题新增一个组件。优先给现有 `LabDef` / `GameQuestion` 增加可选视觉配置，保持向后兼容。

```ts
interface VisualSpec {
  variant?: string
  scene?: string
  unitLabel?: string
  model?: 'ten-frame' | 'number-line' | 'place-value' | 'bar-model' | 'grid' | 'circle' | '3d'
  highlights?: string[]
  labels?: Record<string, string>
}
```

使用规则：

- `variant` 决定同一 kind 下的具体视觉分支，例如 `compare` 可分为 `pairing`、`place-value`。
- `scene` 只放课本情境关键词，例如 `balls`、`hands`、`shopping`、`sports`，不要写展示文案。
- `unitLabel` 必须用于截图中的量词，例如 `根`、`个`、`箱`、`千米`。
- `model` 决定主数学模型，避免组件根据 title 猜测。
- 没有配置时维持当前显示，降低改造风险。

### 3.2 统一视觉骨架

所有 Lab 主可视化区域建议统一为四层：

1. **情境层**：课本对象或抽象对象，显示单位与对象名。
2. **模型层**：十框、数位表、线段图、方格、圆、坐标、三视图等。
3. **操作层**：拖动、圈选、切分、拼合、进位、退位、旋转、投影。
4. **抽象层**：公式、符号、结论，与下方“分步思考”同步。

验收时截图不能只有公式或结果框；主视觉区域必须出现模型层。

### 3.3 状态与动效

每个改造组件至少支持三种状态：

- **初始态**：展示题目情境和可操作模型，不直接抢先解释结论。
- **过程态**：参数变化或答题后，当前步骤高亮，其他步骤降噪。
- **结论态**：模型收束到公式，答案高亮，但原始模型仍可见。

动效只服务数学关系：移动、分组、切分、旋转、投影、进位、退位。不要添加与数学无关的装饰动效。

## 4. 组件级改造规格

### 4.1 g1 `CountGame`：数数与写数

**覆盖题型**：`count`、`write`，重点 P0：`c1-count-01`、`c1-count-02`、`c1-count-04`、`c1-count-05`、`c2-count-02`、`c6-count-02`。

**当前问题**：`count` 主要展示 emoji 串，学生能选答案，但看不到一一对应、圈数、十框结构；`c6-count-02` 存在“10 个手掌”误表达“10 根手指”的风险。

**改成什么样**：

- 数量 0-10 默认改为 **十框 + 对象阵列**：上方显示课本对象，下方显示十框位置。
- 每个对象有序号或逐个点亮轨迹：`1 -> 2 -> ... -> n`。
- FIG 题使用接近课本图的对象类别：球、篮球、积木、彩纸、星星，不再全部用通用 emoji。
- `c6-count-02` 专用 `variant: 'two-hands'`：画两只手，每只 5 根手指；不显示 10 个手掌。
- `write` 题改成 **计数器 + 十框 + 数字符号** 三联：先看数量，再看位值，最后看数字。

**交互**：

- 点击对象时逐个点亮并读数；选择答案后，正确数量全部高亮。
- 错误答案不只显示 wrong，应把多/少的对象数量用淡色提示。
- 写数题拖动计数器珠子时，十框和数字同步变化。

**验收截图**：

- `c1-count-01`：能看见 6 个球按稳定阵列排列，并有 1-6 计数轨迹或圈选。
- `c6-count-02`：只出现 2 只手和 10 根手指，不出现 10 个手掌。

### 4.2 g1 `CompareGame`：比多少与比大小

**覆盖题型**：g1 `compare`，重点 P0：`c1-compare-01`、`c4-compare-01`。

**当前问题**：左右两堆对象 + 符号按钮可以答题，但学生看不到“一一配对后多出来”的理由。

**改成什么样**：

- 主视觉改为 **上下两行对齐配对**，不是两堆散放。
- 每一对对象用细线或共同底色连接。
- 多出来的对象用强调色和标签“多 1 / 多 2”。
- 符号 `>`、`<`、`=` 放在配对结果后出现，而不是一开始作为主视觉中心。

**交互**：

- 选择符号前，允许学生点击“配一配”或自动逐对配对。
- 选错时高亮未配对区域，让学生回到图上看差量。

**验收截图**：

- `c1-compare-01`：红花与绿花逐一配对，绿花多出的 1 朵清楚可见。
- `c4-compare-01`：8 和 6 的差量不是只靠数字，必须能从图中数出来。

### 4.3 g1 `PositionGame`：方位与序数

**覆盖题型**：`position`、`ordinal`，重点 P0：`c3-position-04`。

**当前问题**：一排物体可点击，但缺少起点、方向箭头、参照对象和观察视角；上下/左右/前后容易混淆。

**改成什么样**：

- `ordinal`：显示队列起点箭头，例如“从左数”“从前往后数”，每个位置下方显示序号刻度。
- `position`：显示参照对象卡片，并在其周围绘制上/下/左/右/前/后方向轴。
- 上下题使用竖向布局；左右题使用横向布局；前后题使用纵深队列，不再全部横排。
- 目标对象用描边和参照线，不只靠 emoji 本身。

**交互**：

- 点击参照对象后显示方向轴；点击答案对象后显示从参照到答案的箭头。
- 错误时保留学生点击对象，并显示“你选的是左边/第几”的解释。

**验收截图**：

- `c3-position-04`：能看到猫/鸟的上下关系和竖向参照线。
- 任一序数题：必须看到起点箭头和序号刻度。

### 4.4 g1 `SplitGame` / `AddSubGame` / `TenGame`：分合、加减与凑十

**覆盖题型**：`split`、`addsub`、`ten`。

**当前问题**：算式结果明确，但“分成两部分”“加入/拿走”“凑成 10”的动作不够强。

**改成什么样**：

- `split`：整体区 + 左盘 + 右盘，圆片可拖入两盘；分解式在拖动后生成。
- `addsub`：三段式剧场：原来区、变化区、结果区；加法是对象进入，减法是对象离开或变淡。
- `ten`：10 框吸附卡片，被选卡片填满十框，互补数用空格提示。

**交互**：

- 学生先操作模型，再选答案；不能只点答案。
- 错误时模型保留当前状态，提示缺几个或多几个。

**验收截图**：

- 任一凑十题：截图中应能看到 10 框被选中卡片填满。
- 任一减法题：被拿走对象与剩余对象状态不同。

### 4.5 g2 `NumberLab`：三位数、比较、算盘

**覆盖 kind**：`place-value`、`compare`、`abacus`。

**当前问题**：数位信息已出现，但比较和算盘仍偏结果展示；进位/位值与上珠下珠规则不够显性。

**改成什么样**：

- `place-value`：三列数位表 + 计数器 + 小方块模型。百位显示百方块，十位显示十棒，个位显示小方块。
- `compare`：两个三位数放入并排数位表，从百位开始逐位扫描；第一个不同位放大，其他位降噪。
- `abacus`：保留梁、档、上珠 5、下珠 1；每档旁显示档值，例如“百位：1×100”。

**交互**：

- `compare` 有步骤条：百位 -> 十位 -> 个位 -> 结论。
- `abacus` 点击珠子时显示本档贡献值和累计总数。

**验收截图**：

- `g2-c6-compare`：百位 4 与 3 被高亮，直接推出 402 > 385。
- `g2-c6-abacus`：截图中能区分上珠和下珠，且显示上珠表示 5。

### 4.6 g2 `TwodigitLab` 与 g3/g4 竖式组件：进位、退位、试商、落商

**覆盖组件**：g2 `TwodigitLab`，g3 `MulLab/DivLab`，g4 `DivLab/BigNumLab`。

**当前问题**：当前能展示结果和部分说明，但过程没有形成稳定算法动画：哪一位正在算、进位从哪来、退位拆成什么、试商如何调整，仍不够显眼。

**改成什么样**：

- 加法进位：个位圆片满 10 后捆成 1 根十棒，移动到十位；竖式上方同步出现进位 1。
- 减法退位：从十位拆 1 根十棒为 10 个一，个位再删除减数。
- 乘法竖式：按个位、十位、百位逐步高亮；进位气泡移动到下一位。
- 除法竖式：每轮固定为“看当前位 -> 试商 -> 乘回 -> 相减 -> 落下一位”。
- 试商：除数旁显示“看作整十数”，若乘回过大/过小，显示调商原因。

**交互**：

- 支持步骤播放/暂停/重置；拖动参数后回到初始步骤。
- 每一步只高亮当前参与的数字和模型对象，避免整张竖式同时高亮。

**验收截图**：

- `g2-c7-twodigit-add`：能看到个位 4+8 满十并进 1。
- `g2-c7-twodigit-sub`：能看到十位退 1 拆成 10 个一。
- g4 试商题：能看到除数被估成整十数和试商调整理由。

### 4.7 g3/g4/g6 `SegmentLab`：线段图和数量关系

**覆盖组件**：g3 `SegmentLab`、g4 `SegmentLab/QuantityLab`、g6 `SegmentLab`。

**当前问题**：g3 已捕获 SVG `y` 属性错误；更大的问题是线段图没有统一比例尺、差量/倍量/未知量标注方式不一致。

**改成什么样**：

- 每道线段图都使用同一内部比例尺，最大量作为基准宽度。
- 已知量使用实线段，未知量使用虚线段或问号括号。
- 差量用上方小括号/箭头标注，倍量用重复等长段标注。
- 文字条件与线段标签同色，例如“篮球 50 个”对应蓝色线段。
- `segment-more` 一类必须固定“基准量”，增加/减少部分按基准量的分数或差量显示。

**交互**：

- 鼠标悬停或点击题干条件，高亮对应线段部分。
- 拖动参数时保留比例关系，不允许只改变数字不改线段长度。

**验收截图**：

- `g3-c10-segment-more`：三条线段的 50、65、85 按比例递增，15 和 20 的差量用括号标出。
- `g6-c2-segment-more`：原来 14 天是基准线，增加的 2/7 用单独色块显示。

### 4.8 运动、对称、三视图：`MotionLab` / `ViewsLab` / `Views3DLab`

**覆盖组件**：g3 `MotionLab/ViewsLab/Views3DLab`，g5 `MotionLab/Views3DLab`。

**当前问题**：图形能动，但基准点、对应点、旋转中心、对称轴、观察方向需要更强的数学标注。

**改成什么样**：

- 平移：原图半透明保留，对应点之间画同向等长箭头，箭头旁标格数。
- 旋转：旋转中心固定且高亮，绘制弧形箭头、方向词、角度扇形。
- 轴对称：显示对称轴、对应点连线、垂足和等距刻度。
- 三视图：3D 模型旁固定显示前/右/上投影网格；投影网格不能跟随用户旋转。

**交互**：

- 提供一键切换“前面/右面/上面”视角。
- 悬停小立方体时，在三个投影中同步高亮它贡献的格子。

**验收截图**：

- 平移题截图必须看到原图、终图和对应点箭头。
- 旋转题截图必须看到旋转中心和角度弧。
- 三视图题截图必须同时看到 3D 物体和三个投影。

### 4.9 面积与单位：g4 `ShapeLab/AreaUnitLab/PuzzleLab`，g5 `AreaLab/MeasureLab/PinboardLab`

**覆盖 kind**：周长、面积、面积单位、周长面积变化、多边形面积、公顷、组合图形、钉子板。

**当前问题**：公式展示较直接，但单位方格、剪拼过程、面积一定周长变化、边界点/内部点区分不够系统。

**改成什么样**：

- 周长：只高亮边框路径，面积填充降噪；绕边走一圈后生成周长式。
- 长方形/正方形面积：显示行列网格，“每行几个 × 几行”推出面积。
- 面积单位：1 平方分米拆成 10×10 个平方厘米，强调二维进率 100。
- 多边形面积：剪下的部分要移动到目标位置，拼成已知图形后再出现公式。
- 面积一定周长变化：并排列出不同长宽拼法，面积同色，周长路径长度对比。
- 钉子板：边界点和内部点用不同颜色，公式 `S = I + B/2 - 1` 的 I/B 与图上点联动。

**交互**：

- 支持切换“割补方案”，每块面积单独着色。
- 拖动尺寸时，网格数量、边长标签、公式同步变化。

**验收截图**：

- `g5-c3-area-triangle`：必须看到两个全等三角形拼成平行四边形。
- `g4-c3-peri-area-change`：必须看到面积相同但周长不同的多个拼法。

### 4.10 g6 `CircleLab`：圆、扇形、圆面积、环形、组合图形

**覆盖 kind**：`circle-feature`、`sector`、`circumference`、`circle-area`、`annulus`、`circle-composite`。

**当前问题**：已有 SVG 图形，但圆面积剪拼、圆周率归纳、扇形定义、环形相减等关键过程还偏静态。

**改成什么样**：

- 认识圆：圆心 O、半径、直径同时显示；拖动半径端点时所有半径等长提示保持。
- 扇形：两条半径 + 弧 + 圆心角共同定义扇形，角度变化时区域同步变化。
- 周长：圆沿直线滚动一周，展开成周长线；旁边显示 `C/d` 接近 `π`。
- 圆面积：扇形分割数量可调，左右交错拼成近似长方形；份数越多，边缘越接近直线。
- 环形：外圆面积先出现，再挖掉内圆面积，最后保留环形区域。
- 组合窗户：拆成矩形 + 半圆，尺寸标注分别绑定到公式项。

**交互**：

- `circle-area` 的份数滑块必须改变扇形数量和近似长方形边缘精度。
- `annulus` 的内半径不能大于外半径；如果数据允许接近，应在 UI 上给边界提示。

**验收截图**：

- `g6-c5-circle-area`：左侧圆被切成扇形，右侧拼成近似长方形，标出底≈πr、高=r。
- `g6-c5-annulus`：能清楚看到外圆减内圆，而不是只看到一个带洞圆。

### 4.11 g6 `RatioLab/ScaleLab/PositionLab`：比例、比例尺、确定位置

**覆盖 kind**：比、比值、化简比、按比例分配、比例性质、解比例、黄金比、放大缩小、比例尺、数对、方向距离。

**当前问题**：公式清楚，但“两个量的顺序”“同时除以同一个数”“内外项积”“比例尺单位统一”“先列后行”需要更强的图形约束。

**改成什么样**：

- 比的认识：两条量条保留前项/后项颜色，交换顺序时读法和颜色同步变化。
- 化简比：两条量条同步按公因数分组，同时除以同一个数后收束为最简比。
- 按比例分配：总量条被切成比例份数，先求一份，再合并每个部分。
- 比例基本性质：比例式上用交叉线连接内项和外项，两个乘积并排比较。
- 解比例：从内外项积相等生成方程，再逐步求 x。
- 放大缩小：方格纸上原图和新图并排，对应边同色并标比例。
- 比例尺：先统一单位，再用比例尺条从图上距离映射实际距离。
- 数对：列轴和行轴分色，先列后行，交点高亮。
- 方向距离：罗盘、基准方向、偏转角、距离比例尺和目标点同时出现。

**验收截图**：

- `g6-c4-ratio-distribute`：总量 500g 被切成 3+2 份，并显示每份 100g。
- `g6-c7-direction`：从正北/正南出发的偏转角和 3 千米距离都可见。

### 4.12 数据、概率、因数倍数、字母式

**覆盖组件**：g3 `TallyLab`，g5 `ChartLab/ChanceLab/NumberLab/FormulaLab`。

**当前问题**：多数题能显示表或图，但从原始记录到统计图、从实验到概率、从拼图到因数、从变化情境到字母式的抽象链条还可以更完整。

**改成什么样**：

- 正字统计：每点击一次生成一笔，5 笔合成一个“正”，频数表同步更新。
- 统计表/条形图：表格单元格和柱子互相高亮，合计行/列独立显示。
- 转盘/摸球：理论概率和实验频率并排；每次实验追加到记录区。
- 因数：用方块拼长方形，成对因数同时出现。
- 倍数：在数轴上按固定步长跳跃，落点形成倍数集合。
- 质数筛：按 2、3、5、7 的倍数逐轮筛除，并显示筛除原因。
- 字母式：动态生成 n 个对象，再把变化数量替换成字母表达式。

**验收截图**：

- `g5-c6-prime-sieve`：能看到被筛除数字及其筛除轮次。
- `g5-c7-frog-song`：n 只青蛙与嘴、眼、腿数量的字母表达式同步出现。

## 5. 数据与代码落点

| 层 | 具体改动 | 原则 |
|---|---|---|
| 数据层 | 给需要区分场景的题增加可选 `visual` 配置 | 不破坏现有 `params/formula/config`；无配置走旧逻辑 |
| 计算层 | `computeLab` 增加可用于渲染的中间量，如分组、位值、线段比例、步骤状态 | 不把复杂计算塞进模板表达式 |
| 组件层 | 每个 Lab 组件内部按 `variant/model` 分支 | 同类数学模型复用子组件，不复制整套模板 |
| 样式层 | 使用现有 Nuxt UI token 和 `--ui-*` 变量 | 不硬编码新色板；截图可读性优先 |
| 测试层 | 组件测试覆盖新增 variant；截图脚本重跑 P0/P1 | 防止图形空白、NaN、SVG 属性表达式字符串化 |

建议先抽出以下小组件，减少重复：

- `TenFrame.vue`：十框、逐个计数、凑十。
- `PairingRows.vue`：两行对象一一配对和差量。
- `PlaceValueTable.vue`：百/十/个或更高数位表。
- `StepVerticalCalc.vue`：乘除竖式步骤高亮。
- `BarModel.vue`：线段图、差量、倍量、未知量。
- `GridPaper.vue`：面积、放大缩小、坐标。
- `CircleMeasure.vue`：圆心、半径、直径、弧、扇形。

## 6. 验收流程

每完成一个组件族，执行以下检查：

1. 跑对应年级 `npm run test`，确保数据校验和组件测试通过。
2. 重新生成或启动静态页面，对该组件族覆盖的例题重截截图。
3. 对照 `docs/example-visual-review.md` 中同 id 的“改进方案”逐项勾验。
4. 截图不得出现空白、`加载可视化…`、SVG 属性错误、NaN、单位缺失。
5. 至少抽查桌面 1440px 和移动 390px 两个视口；移动端模型可纵向堆叠，但关键标签不能消失。
