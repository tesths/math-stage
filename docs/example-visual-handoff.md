# 六册例题可视化交接文档

> 交付日期：2026-08-10  
> 交付范围：`g1`-`g6` 上册全部结构化例题与 Lab，共 235 条。  
> 交付性质：调研、review、截图证据、组件级实施规格。本轮不包含源码改造。

## 1. 交付包内容

| 文件 | 用途 | 交接时怎么用 |
|---|---|---|
| [`docs/example-visual-review.md`](example-visual-review.md) | 逐册逐题 review 总表 | 每一道例题的截图、题源证据、当前问题、改进方案和优先级都在这里。开发时先按例题 id 查这一张表。 |
| [`docs/example-visual-upgrade-spec.md`](example-visual-upgrade-spec.md) | 组件级实施规格 | 回答“要改成什么样”。开发时不要逐题临场设计，先按组件族套用这里的规格。 |
| [`docs/visual-review-screenshots/`](visual-review-screenshots/) | 当前页面截图证据 | 每道例题一张截图，用来确认当前问题、复核改造前状态，也作为后续视觉回归的基线。 |
| [`docs/visual-review-screenshots/manifest.json`](visual-review-screenshots/manifest.json) | 截图清单 | 记录 235 条截图路径、路由和异常 notes。后续重截后可对照更新。 |

## 2. 阅读顺序

1. 先读本文档，确认交付物、优先级和开发切分方式。
2. 打开 [`example-visual-review.md`](example-visual-review.md)，按 `P0 -> P1 -> P2` 读逐题矩阵。
3. 打开 [`example-visual-upgrade-spec.md`](example-visual-upgrade-spec.md)，按组件族认领任务，不要按 235 条例题逐个写独立组件。
4. 开发某一道题时，同时打开 review 行、截图和组件规格：review 负责说明“这道题哪里不准”，规格负责说明“应该改成什么样”。
5. 改完后重截对应页面，和 `visual-review-screenshots/` 里的旧截图对照，确认数量、单位、方向、比例、步骤没有回退。

## 3. 总体改造目标

这批改造不是单纯把页面做漂亮，而是给每道例题补齐稳定的数学证据链：

```text
课本情境/真实对象 -> 可操作数学模型 -> 图形变化过程 -> 算式/结论
```

开发时每个主可视化都要同时满足四点：

- 学生能看见题目里的关键对象、单位、数量、方向或比例。
- 学生能看见对象如何分组、对齐、切分、拼合、旋转、投影、进位或退位。
- 下方公式或步骤与图上的高亮状态一一对应。
- 截图里不能只有公式、结论框或装饰图，必须有明确数学模型。

## 4. 优先级与第一批任务

### 4.1 优先级定义

| 优先级 | 数量 | 处理原则 |
|---|---:|---|
| P0 | 11 | 先修。包含图内数量题、对象单位误导和真实渲染错误。P0 没处理完前，不建议进入大规模美术升级。 |
| P1 | 85 | 第二批。重点是空间关系、位值、线段图、几何比例、运动过程等概念模型。 |
| P2 | 139 | 第三批。题源基本准确，主要增强清晰度、交互反馈和情境贴合。 |

## 5. 建议开发切分

### 5.1 Task A：修复并升级线段图

| 项目 | 内容 |
|---|---|
| 范围 | `g3/game/src/components/labs/SegmentLab.vue`，后续同步检查 g6 `SegmentLab`。 |
| 先修问题 | 把类似 `y="36 + bi * 56"`、`y="68 + bi * 56"` 的 SVG 字符串属性改成绑定表达式。 |
| 视觉目标 | 同类数量按同一比例尺绘制；差量、倍量、未知量用括号、箭头和标签标清。 |
| 验收截图 | `g3-c10-segment-more`、`g3-c10-times-word` 不再有 SVG 报错，线段间距和标签位置正确。 |

### 5.2 Task B：升级一年级数数、比较和方位

| 项目 | 内容 |
|---|---|
| 范围 | `CountGame.vue`、`CompareGame.vue`、`PositionGame.vue`、`OrdinalGame` 对应组件，如当前实现被拆在其他文件，以实际路由组件为准。 |
| 视觉目标 | 数数用对象阵列 + 十框 + 计数轨迹；比较用一一配对；方位用参照物、视角箭头和轴线。 |
| 数据要求 | FIG 题先按课本截图校准数量和对象类别，不要用随机 emoji 代替图内信息。 |
| 验收截图 | P0 的 g1 截图能直接看出数量、比较关系或空间关系，不需要只读题干文字。 |

### 5.3 Task C：升级二年级位值与竖式

| 项目 | 内容 |
|---|---|
| 范围 | `g2/game/src/components/labs/NumberLab.vue`、`TwodigitLab.vue`，以及同类计算 Lab。 |
| 视觉目标 | 数位表、十个一换一个十、进位、退位、竖式对齐同步展示。 |
| 交互要求 | 拖动或点击步骤时，高亮当前位、来源量和结果量；错误时指出错在位值还是运算。 |
| 验收截图 | 一眼能看到个位、十位、进位或退位，不只是最终竖式答案。 |

### 5.4 Task D：升级六年级圆、比、比例尺和位置

| 项目 | 内容 |
|---|---|
| 范围 | `CircleLab.vue`、`RatioLab.vue`、`ScaleLab.vue`、`PositionLab.vue`。 |
| 视觉目标 | 圆显示圆心、半径、直径、周长展开和面积剪拼；比和比例尺显示同单位换算、线段比例和实际距离；位置显示坐标、方向和参照系。 |
| 验收截图 | 尺寸、单位和比例关系能从图上读出来，公式只是收束，不替代模型。 |

## 6. 逐题开发方法

开发任意一条例题时，按下面流程走：

1. 在 [`example-visual-review.md`](example-visual-review.md) 搜索例题 id，比如 `g3-c10-segment-more`。
2. 打开该行截图，确认当前页面具体长什么样。
3. 读该行的“当前问题”和“改进方案”，确定这道题的准确性风险。
4. 到 [`example-visual-upgrade-spec.md`](example-visual-upgrade-spec.md) 找对应组件规格，比如 `SegmentLab`、`CountGame`、`CircleLab`。
5. 优先改组件族和轻量配置，不为每道题新建独立组件。建议用 `VisualSpec` 承载 `variant`、`scene`、`unitLabel`、`model`、`highlights`、`labels`。
6. 改完本组件族后，至少抽查该组件族的第一题、P0/P1 题和最后一题，避免只修一个样例。
7. 重截改动题目的页面，和旧截图对比，确认没有数量、单位、方向、比例和标签回退。

## 7. 验收标准

| 类型 | 必须满足 |
|---|---|
| 准确性 | 数量、单位、方向、比例、线段长度、圆的半径/直径、坐标位置和算式参数与题源一致。 |
| 过程表达 | 至少有初始态、过程态、结论态；关键步骤必须有图形高亮，而不是只更新文字。 |
| 组件复用 | 同一类题优先由同一组件族和 `VisualSpec` 支撑，避免 235 个一次性实现。 |
| 截图回归 | P0/P1 改动后必须保留新截图；异常页面必须在 `manifest.json` notes 中能看出是否已解决。 |
| 用户体验 | 主视觉区域层级清楚，模型、操作和公式不互相遮挡；移动端截图不能出现文字溢出。 |

## 8. 不建议做的事

- 不要只做视觉美化，不补数量、单位、方向、比例和步骤证据。
- 不要把 FIG 题直接替换成通用 emoji，必须先校准课本图内数量和对象类别。
- 不要为每道题新建独立组件，优先扩展现有组件和配置。
- 不要让公式或答案框成为主视觉，公式应来自图形过程。
- 不要在 P0 未修完时批量做 P2 美术细节。

## 9. 交接建议

建议把开发分成四个 owner 或四个迭代：

| 迭代 | owner 建议 | 交付物 |
|---|---|---|
| 第 1 批 | 线段图 + P0 负责人 | 修完 11 个 P0，更新截图和异常 notes。 |
| 第 2 批 | 低年级互动负责人 | 完成 g1 数数、比较、方位、分合、加减、十框体系。 |
| 第 3 批 | 位值与计算负责人 | 完成 g2-g4 数位、竖式、进退位、试商和混合计算。 |
| 第 4 批 | 几何与高年级负责人 | 完成运动、面积、圆、比例尺、位置、统计概率和代数类升级。 |

最终交付时，开发同事需要回填三类证据：已改组件列表、已重截截图列表、仍需人工核对的 FIG 题列表。
